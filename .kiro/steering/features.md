# Високорівневий список фіч

Довідковий документ із переліком усіх функціональних можливостей системи, згрупованих за модулями та ролями.

## Публічні сторінки (без автентифікації)

- Головна сторінка
- Ліцензія / умови використання
- Політика конфіденційності

## Автентифікація

- Вхід через Google OAuth
- Автоматичне створення облікового запису при першому вході
- Вихід із системи

## Онбординг нового користувача (Player Claim)

- Пошук існуючого гравця за ПІБ (з фільтрацією за країною та містом)
- Заявка на привʼязку до існуючого гравця
- Заявка на створення нового гравця (місто та країна необовʼязкові; якщо вказано місто — потрібно вказати і країну; вибір країни зі списку та міста каскадом країна → місто; країна — лише з довідника, місто можна ввести вручну)
- Очікування модерації заявки

## Основні сторінки (ROLE_PLAYER)

### Турніри

- Список опублікованих турнірів із пагінацією та фільтрами за назвою, періодом (минулий / активний / майбутній), форматом і режимом проведення
- Картка турніру: загальна інформація, формат, дедлайни, офіційні особи
- Результати турніру: загальна таблиця результатів усіх команд
- Детальні результати: розбивка по турах і запитаннях
- Окремі дати приховування результатів (`resultsHiddenUntil`) і деталей (`detailsHiddenUntil`); до відкриття доступ мають офіційні особи турніру
- Неопублікований турнір (картка, результати, детальні результати, сесії та картка сесії) бачать лише його організатори та модератори; решта отримує 404 (`TournamentAccessService::isVisible`)
- За однакових балів місце дорівнює середньому зайнятих позицій (наприклад, спільні 2–3 місця дають 2,5)
- Сесії турніру: перелік ігрових сесій із місцем проведення, датою та посиланням на анонс гри (за наявності)
- Картка сесії: склади команд, відповіді, спірні відповіді, посилання на анонс гри (за наявності)

### Команди

- Список команд із пагінацією та пошуком (фільтрація за країною та містом, каскадом країна → місто)
- Картка команди: базові склади за сезонами, місто та країна, капітани
- Турнірна історія команди
- Можливість подати заявку на капітанство

### Гравці

- Список гравців із пагінацією та пошуком (фільтрація за країною та містом, каскадом країна → місто)
- Профіль гравця: ПІБ, місто та країна, контакти (для модераторів та власника)
- Турнірна історія гравця
- По-сезонна історія базових складів і участі в турнірах

### Майданчики

- Список затверджених майданчиків із пошуком (фільтрація за країною та містом, каскадом країна → місто)
- Картка майданчика: назва, місто та країна, опис (з клікабельними посиланнями) та посилання, список турнірів, що проводилися (з посиланням на анонс гри для кожного відіграшу, за наявності)

## Особистий кабінет (My)

### Контакти

- Перегляд і оновлення контактної інформації (Telegram, Facebook, телефон)

### Майданчики

- Список майданчиків, якими гравець може керувати: створені ним плюс ті, де він представник (без дублів)
- Створення нового майданчика (з опційними описом та посиланням)
- Керувати майданчиком (перегляд у списку, редагування, оновлення) може як його творець, так і будь-який представник — з однаковими правами
- Редагування майданчика: опис і посилання доступні для редагування будь-коли (і до, і після схвалення); список представників можна редагувати лише після схвалення майданчика

### Управління командою (капітан)

- Перегляд поточного складу
- Додавання гравців до команди
- Виключення гравців зі складу
- Вихід із команди для гравця, який не є капітаном; капітан має спершу передати капітанство
- Передача капітанства іншому гравцю складу
- Максимум 9 гравців у базовому складі; максимум 2 приєднання гравця до команд за сезон
- Редагування інформації про команду

### Турніри (організатор)

- Список турнірів, створених поточним гравцем
- Створення турніру (чернетка)
- Редагування турніру; після початку опублікованого розподіленого турніру змінюється лише посилання на обговорення
- Назву опублікованого турніру змінювати не можна
- Турнір може тривати в межах кількох сезонів; сезон турніру визначається за датою завершення
- Видалення чернетки
- Подання турніру на модерацію
- Окрема публікація організатором після схвалення модератором та перевірки обовʼязкових даних
- Додавання / видалення пакета запитань організатором; отримати файл можуть лише поточні ведучі схвалених відіграшів цього турніру
- Призначення офіційних осіб (редактор, організатор, ігрове журі, апеляційне журі)

### Заявки на проведення сесій (представник)

- Список заявок на проведення по всіх майданчиках, представником яких є гравець (заявки спільні для всіх представників майданчика, а не лише того, хто подав; з посиланням на анонс гри, за наявності)
- Заявку можна подати лише на опублікований турнір і до дедлайну реєстрації (для очного — поки турнір опублікований); так само подання результатів відкрите лише для опублікованого турніру
- Подання заявки одночасно створює сесію та заявку зі статусом `pending` (з обовʼязковим призначенням ведучого — гравця з акаунтом; з опційним посиланням на анонс гри)
- Редагування / видалення заявки будь-яким представником майданчика (посилання на анонс гри редагується поки відкрита реєстрація)
- Повторне подання відхиленої заявки на розгляд організатору

### Відіграші ведучого (ведучий)

- Список власних відіграшів, де гравець призначений ведучим (лише схвалені)
- Сторінка конкретного відіграшу з доступом до пакета запитань турніру
- Кожне завантаження пакета фіксується в `TournamentDocumentDownload`
- Історія ведучих фіксує ведучого при схваленні заявки та його заміни, поки заявка схвалена; призначення лише на етапі очікування до історії не потрапляють
- Гравця не можна додати до складу в цьому турнірі, якщо він одночасно є в історії ведучих і завантажував пакет цього турніру, навіть після заміни ведучого
- У списку сесій історію ведучих і ознаки завантаження бачать організатори та модератори для всіх сесій, представники — для своїх майданчиків; інші гравці бачать поточного ведучого

### Подання результатів сесії (представник)

- Внесення, редагування та видалення складів команд на сесії (від 1 до 9 гравців)
- Створення нових команд і гравців безпосередньо у формі складу; разова назва команди для відіграшу, необовʼязкова позначка капітана (склад можна зберегти без капітана)
- У новоствореного гравця місто та країна необовʼязкові; якщо вказано місто (вибране зі списку або введене вручну) — потрібно вказати й країну, а поле міста лишається заблокованим до вибору країни
- Таблиця складу показує місто та країну (якщо є) окремою колонкою для всіх гравців — і підтягнутих існуючих, і новостворених
- Легіонери визначаються за належністю до базового складу на дату гри; дублювання команди або гравця в турнірі заборонено
- Доступ відкритий для схваленої сесії з датою гри не пізніше сьогодні, поки не закрито подання результатів
- Завантаження XLSX-шаблону з командами, турами та наявними відповідями; потрібні склади й задана структура запитань
- Завантаження заповненого XLSX до 5 МіБ: перевіряються розширення та MIME-тип, належність команд до сесії, номери турів і повнота відповідей усіх команд
- Значення `0` / `1` позначають неправильну / правильну відповідь, порожня клітинка — `0`; інші суто цифрові значення відхиляються, решта тексту — спірна відповідь до 500 символів
- Завантаження зберігає відповіді до подання; окрема дія подання позначає результати поданими, перераховує бали та автоматично подає створені спірні
- Доступ до внесення результатів має будь-який представник майданчика сесії, а не лише той, хто подав заявку

### Управління заявками на сесії (організатор)

- Перегляд заявок на проведення сесій свого турніру (окремі секції: на розгляді, схвалені, відхилені; з посиланням на анонс гри, за наявності)
- Затвердження / відхилення / відкликання заявок
- Повторне затвердження раніше відхиленої заявки (відхилені заявки не зникають, а зберігаються з причиною відмови)

### Спірні відповіді (Disputes)

- Подання спірної відповіді
- Перегляд поданих спірних
- Видалення спірної (до подання)

### Апеляції (Appeals)

- Подання апеляції (на зарахування відповіді або зняття запитання)
- Перегляд апеляцій свого турніру
- Прийнята апеляція типу `remove` знімає запитання в усьому турнірі та перераховує бали всіх команд

### Розгляд спірних (ігрове журі)

- Список турнірів зі спірними для розгляду
- Прийняття / відхилення спірної з коментарем

### Розгляд апеляцій (апеляційне журі)

- Список турнірів з апеляціями для розгляду
- Прийняття / відхилення апеляції з вердиктом

## Модерація

### Заявки гравців

- Список заявок на привʼязку до гравця (з відображенням країни та міста)
- Затвердження / відхилення заявки (для нового гравця модератор може скоригувати місто в межах країни заявки)

### Заявки на капітанство

- Список заявок на капітанство
- Затвердження / відхилення з коментарем модератора

### Майданчики

- Список незатверджених майданчиків (з описом та посиланням заявки для перегляду)
- Затвердження / відхилення майданчика

### Модерація турнірів

- Список турнірів на модерації
- Схвалення / відхилення заявки на модерацію турніру з коментарем; схвалення саме по собі не публікує турнір

### Управління користувачами

- Блокування користувача з вказанням причини
- Розблокування користувача

## API (AJAX-ендпоінти)

- Автокомплект країн (`ROLE_USER`)
- Автокомплект міст
- Автокомплект гравців
- Автокомплект команд
- Отримання гравців команди на сесії
- `/api/menu-counts` (`ROLE_PLAYER`): лічильники заявок організатора, поданих спірних і апеляцій для відповідного журі; модератору також доступні лічильники модерації. Позначки меню оновлюються після часткових оновлень сторінки

## Ролі та доступ

Ієрархія: `ROLE_ADMIN` → `ROLE_MODERATOR` → `ROLE_PLAYER` → `ROLE_USER`

| Роль | Доступ |
|------|--------|
| Анонім | Головна, ліцензія, політика конфіденційності, OAuth-ендпоінти |
| ROLE_USER | Player Claim (заявка на привʼязку до гравця), автокомплект країн/міст/гравців |
| ROLE_PLAYER | Усі основні сторінки (турніри, команди, гравці, майданчики), особистий кабінет |
| ROLE_MODERATOR | Панель модерації (заявки, майданчики, турніри, користувачі) |
| ROLE_ADMIN | Успадковує права модератора; не обходить перевірки звʼязків організатора, представника, ведучого чи журі |

Додаткові ролі (не в ієрархії Symfony, визначаються зв'язками):

| Роль | Опис |
|------|------|
| Капітан | Управляє складом команди (визначається через TeamPlayer.isCaptain) |
| Організатор | Створює та управляє турнірами (визначається через TournamentOfficial) |
| Представник | Подає заявку на проведення відіграшу, вносить результати (визначається через VenueRepresentative — належність гравця до майданчика сесії; заявка спільна для всіх представників майданчика). Поле TournamentSession.representative фіксує лише того, хто подав заявку |
| Ведучий | Веде відіграш; має доступ до пакета запитань схваленого відіграшу (визначається через TournamentSession.host) |
| Ігрове журі | Розглядає спірні відповіді (визначається через TournamentOfficial.role = game_jury) |
| Апеляційне журі | Розглядає апеляції (визначається через TournamentOfficial.role = appeal_jury) |

## Ключові бізнес-процеси

### Життєвий цикл турніру

```
Чернетка → Подання на модерацію → Очікує модерації → Схвалено → Публікація організатором
                                               → Відхилено (публікація недоступна)
```

### Життєвий цикл заявки на сесію

```
Подання (створює сесію та заявку) → Очікує (pending) → Затверджено / Відхилено
Затверджено → Відкликано
Відхилено → Затверджено (організатор передумав)
Відхилено → Очікує (представник подав повторно)
```

### Процес спірної відповіді

```
Створено → Подано → Прийнято / Відхилено (ігрове журі)
```

### Процес апеляції

```
Очікує → Прийнято / Відхилено (апеляційне журі)
Типи: зарахування відповіді / зняття запитання
```

### Процес заявки на капітанство

```
Очікує → Затверджено / Відхилено (модератор)
```

### Процес привʼязки гравця

```
Подано → Затверджено / Відхилено (модератор)
```

## Формати турнірів

- **Централізований** — одна сесія в одному місці
- **Розподілений** — кілька сесій на різних майданчиках

## Режими проведення

- **Офлайн** — очна гра
- **Онлайн** — дистанційна гра
- **Змішаний** — комбінований формат

- Майданчик і сесія мають окремі ознаки `isOnline`; онлайн-майданчик привʼязується до спеціального міста для онлайн-ігор
- Для онлайн-турніру сесія онлайн, для офлайн-турніру — офлайн (онлайн-майданчик недопустимий); у змішаному режимі враховуються ознака майданчика та вибір у заявці

## Сезони та інфраструктура

- Перехід до наступного сезону через `app:season:rollover`: переносяться лише гравці базового складу, які грали за цю команду в сезоні; капітан зберігається або обирається за кількістю ігор (за рівності — найменший ID)
- Режим технічних робіт: стан у Redis із TTL 24 години; модератори й адміністратори зберігають доступ, решта отримує 503. OAuth, вихід і шляхи профайлера залишаються доступними
- Банер альфа-тестування ввімкнений за замовчуванням; `ALPHA_TESTING_MODE=0` у середовищі застосунку приховує його, не змінюючи права доступу
- Sentry: необовʼязковий `SENTRY_DSN`, позначення середовища, контекст журналювання та очищення чутливих полів запиту; трасування продуктивності вимкнене
